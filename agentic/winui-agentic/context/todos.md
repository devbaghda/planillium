### 2026-10-26 — B1f cursor jump to the salary box on a blank click, agentic side (`pilot-specs/b1f-focus-jump/`, no SPEC)

Root cause: `SectionScroll` (a ScrollViewer, not a tab stop) answers a left-button release that no control claimed by focusing its first focusable child (the salary box), but only when focus is not already inside it. The page's press handlers park focus on `FocusPark`, which is outside the scroller, one dispatcher turn after the press. Real mouse (~100 ms hold): the park lands first, the release then pulls focus into the salary box as a Mouse move, which the B1d guard allows. Scripted click (0 ms hold): release before the park, no jump; that is why B1d QA missed it. Reproduced with SendInput down/120 ms/up: 8/8 jumps (0 ms hold: 1/8). Also jumped from the section list, after a window switch and after a wheel scroll. Fix: the scroller's content Grid (`SectionContent`, transparent background) marks unclaimed `PointerReleased` handled (`SettingsPage.SectionContent_PointerReleased`), so the scroller's focus step never runs; presses untouched. `AllowFocusOnInteraction=False` on the scroller was tried and rejected: inherited, boxes stopped taking focus on click. Coder probe (scratch `MENTOR_ROOT`, SendInput, 120 ms hold, 11 blank/heading points over the pane, from name box / new-tag amount / salary / Studioshoo / section list / after window switch / after wheel): fix off 77/77 jumps, fix on 0/154, every source box still took focus. Strict build 0/0, tests 362/362.
QA round 1 on d2d30b0: FAIL. The 4 px right-edge padding strip of the Settings scroller was unclaimed and still jumped to the salary box (8/18, 17/27 jumps with hold >= 50 ms); interior clean in 600+ trials. Fix pass 1 e82135f: the padding moved inside the claiming content (`SectionContent`) and the content fills the viewport height, so the edge is claimed. Awaiting QA re-run on e82135f (edge-strip cases + regression). Standing lesson added to `DECISIONS.md` (WinUI / layout).
