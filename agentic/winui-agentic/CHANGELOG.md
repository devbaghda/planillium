# Planillium App — Changelog

## Unreleased

- Fix: Settings -> AI: an API key is stored only when you press Save or Enter in the key box. Pressing Enter in the Model or monthly limit box saves only that box; clicking empty space (or Esc) with a key typed empties the key box and stores nothing.
- Fix: Settings: Esc in any text or number box (name, hours, scoring, keywords, idle, AI key, model, monthly limit) takes the cursor out, puts the saved value back and removes the message about what was typed. Clicking empty space takes the cursor out too; Tab or Shift+Tab afterwards continues from the box you left. Number boxes' up/down buttons work as before.
- Fix: Settings -> AI: the model name and the monthly limit are saved when you leave the box or press Enter, not only with Save; the model box always shows the saved model.
- Change: Settings -> Income: the salary, payable-tag amounts and a new tag's amount accept at most EUR 100 000,00 a month. A higher amount shows "Amount is too large - at most EUR 100 000,00 a month. The saved amount was kept." and nothing is saved.
- Fix: Reports: a week's "Of which paid work" figure is now the same to the cent in the Week, Month and Year views; the Total is still the sum of the rows shown.
- Fix: Reports, Time diary: a payable tag whose name matches a built-in tag apart from capital letters (for example "Studioshoo") is listed once in the tag filter and the Edit/Split tag lists, with one "Mark all" button.
- Fix: Reports, Time diary, App filter: rows titled "- Telegram" or "– Telegram" (Telegram with no chat name) now count under "Telegram", not "Other".
- Fix: Reports summary table: the "Income lost/gained" and "Of which paid work" headers wrap onto two lines, so the table fits the default window more often; when it still does not fit, it scrolls sideways as before.
- Fix: Settings -> AI, monthly limit: a negative limit now says "must be more than 0", like zero. After a refused limit or key, editing that box clears the message. The "This month" spend line updates after every AI call, without leaving Settings.
- Change: a test copy of the app (started with MENTOR_ROOT set) never uses Windows Credential Manager, not even a test entry; an AI key saved there is kept in memory for that run only. Normal runs are unchanged.
- Fix: Ask Claude and plan files: JSON reading and writing no longer depends on a .NET default that can be switched off, so a compact Claude reply always turns into a preview.

- New: monthly AI cost limit. Settings -> AI shows "Monthly AI limit (EUR)" (default 5) and "This month: EUR x of EUR y used (estimated)". When the month's estimated cost reaches the limit, Ask Claude and Test connection are refused before anything is sent, with a message saying the limit was reached, how much was spent and where to raise it; plans, prompts and non-AI features are unaffected, and the copy-the-prompt route still works. The spend restarts at zero each calendar month. An empty, negative, zero or text limit is refused with a message and not saved. The cost is an estimate (reply size at Anthropic's list prices), not an invoice.
- Fix: Time diary: a Telegram chat whose name contains " - " (for example "Team - Alpha") is now told apart by its whole chat name in the App/Page columns, the filters and search, instead of being split at its own dash and landing under a wrong app. Telegram windows without a chat name still show as plain "Telegram"; other apps are unchanged.

- Change: the "Today" item in the left sidebar shows a dot only while the overdue banner shows on the Today page, and on every page. It goes away as soon as the last overdue task is rescheduled, completed or covered by a day off, and appears when a task becomes overdue (midnight rollover, plan change); no restart needed. What counts as overdue, the banner and scoring are unchanged.

- Fix: clicking empty space no longer pushes the cursor into a text box anywhere in the app, and it takes the cursor out of the box it was in — the same protection Settings -> Income already had, now also on the other Settings sections (General, Hours, Scoring, Keywords, Idle, AI), Today and Schedule (task notes), Reports (Diary search) and every dialog with a text box (Add plan, Add task, Edit/Split diary entry, Welcome back, Name setup, Replace remaining tasks, Evening review, Spend, TickTick connect). Tab, clicking into a box and Settings -> Income work as before.

- Change: the Reports Diary no longer stops at 300 rows. "Show N more" keeps growing the list up to "Show all", and "Select all" ticks every matching entry (the count shown equals the number of matches). Filters, search and marks work as before.

- Change: Reports, Time diary, App filter: entries that are a window title without a dash (for example "74% complete" or "Add a device") are gathered under one entry, "Other", listed last; choosing it shows exactly those rows. Real program names (and known ones such as Chrome, Excel, Telegram) stay individual. The App column of each row is unchanged. Counts, other filters, search, Show all and Clear work as before.
- Change: Ask Claude (Add plan and Replace remaining tasks) now asks Claude for a compact reply: one minified JSON block, the briefing only inside it (not also written out as text), short fields. The prompts are 10-38% shorter and a sample 14-task plan reply is about 43% smaller, so Claude answers faster. The plan, tasks, preview and Apply look exactly the same; the wait limit and Cancel are unchanged. A full-form plan (pasted, loaded from a .json file, or from an older prompt) still imports as before; a compact reply that is malformed is refused with a message and nothing is added.
- Fix: a test copy of the app (started with MENTOR_ROOT set) no longer reads, switches or deletes the real "Start with Windows" setting; the toggle then shows off and does nothing. Normal runs are unchanged.

- Fix: marks on the Diary no longer disappear. A gap you had already marked was deleted and written again as "unaccounted" when the idle question for it was later answered or skipped; now it is left as you marked it and no second row is added.
- Change: Diary "Mark on-plan / off-plan / neutral" now reaches every entry that matches the current filters, not only the 300 shown; the buttons show the count ("Mark 7,200 as on-plan", or "Mark 3 ticked" when rows are ticked). Ticks stay after a mark, a filter change or a refresh. Before anything is written a dialog shows how many rows will be filled, overwritten and left unchanged. The tag buttons act on ticked rows only and use the same dialog.
- New: every bulk mark makes a dated backup of the diary first (the last 5 are kept) and can be undone: from the message under the Diary toolbar, or later in Settings > Change history (last 20 changes, kept 30 days). Undo puts back the old values; rows you edited or that were removed since are left alone and counted. Undo also forgets the activity keywords the mark taught (each goes back to the list it was in).
- Change: the Diary tag buttons (each tag and "Clear tag") now work on every entry matching the current filters when nothing is ticked, like the category buttons, with the same count in the button text, the same confirm dialog, backup and Undo. A mark with nothing ticked no longer teaches activity keywords (marks of ticked rows still do). Undo in Settings > Change history asks for confirmation first. "Show all" now lists every match (the 300-row cap holds until you press it). Settings > Change history says backups hold full window titles and that the last 5 are kept.
- Change: a category mark still applies to idle rows, but idle rows no longer teach activity keywords, so "idle" is never learned as a keyword (the confirm dialog says so).
- Change: "Clear activity history" and "Clear all my data" also delete the diary backups and the Change history, and say so in their dialogs; they now run even when only backups or history are left.

- Fix: Reports uses far less memory with a long time diary. Measured on a test copy with 9300 diary entries: opening Reports with "All time" on went from 128 MB to 87 MB; after "Show all" and switching periods it stays near 70-80 MB (was up to 1.4 GB), and leaving Reports gives the memory back (was 0.9-1.2 GB held while on another page). The diary list now creates only the rows on screen (more as you scroll); switching Day/Week/Month/Year or opening a pie slice no longer rebuilds the diary; the 30-second live refresh does nothing when no new entry was logged; Reports is rebuilt when you come back to it and returns to where you had scrolled. Rows, totals, "Showing N of M", Show more/Show all and the 300-row cap are unchanged. The App and Page filter lists are built when you open them; they no longer show up empty after a period switch.
- Fix: Ask Claude can now return a long reply (a rewrite of a 34-task plan was cut off at 8000 tokens). The reply limit is now 16000 tokens and Planillium waits up to 4 minutes (was 2) before giving up; the "Gives up after ..." line and the timeout message say 4 minutes. A reply that still hits the limit shows the same "cut off" message.
- Change: the one-time Anthropic notice in Ask Claude is set in smaller type (body 11.5, headings 12, last line 11, was 13) and takes less space.
- Change: the Replace remaining tasks dialog is wider (760) and taller on a large window, so its vertical scrollbar no longer shows at default size; on a small window it still scrolls and the buttons stay visible.
- Change: the Plans page buttons per plan are now "+ Add task", "Replace remaining…", "Archive" and a "More" menu (Briefing, Excluded days…, Teach on-plan apps…); cards sit 12 px apart. The Ask Claude "Stop" button has a tooltip saying it cancels the request and changes nothing.

- Fix: a test copy of the app (started with MENTOR_ROOT set) no longer reads, saves or deletes your real AI key or TickTick credentials in Windows Credential Manager, and never contacts Anthropic or TickTick (the local test stub still works). In such a copy, "Ask Claude" shows "AI is off in this test copy...", Settings -> AI refuses to save a key with the same reason, and TickTick "Save & authorize" says "TickTick is off in this test copy..." without opening the browser. Normal runs are unchanged.

- Change: Reports summary table (Day, Week, Month, Year) has two new columns after Score: "Income lost/gained" (red when negative, green otherwise) and "Of which paid work" (light green). Day and Week show one row per day, Month one per week, Year one per month; the Total row shows the period figure and the rows add up to it to the cent. The Score card and the "Income lost or gained / Of which paid work" row above the table are gone (the "days off marked" count went with the Score card). A table with a single row (Day, a Monday-only Week, a Month with one week, a Year with one month) shows no Total row; two or more rows keep it. Year also lists a month that has income but no logged activity.
- Fix: Reports, Time by app: rows you can open show their chevron again, and the pie slices now have different colours (the list swatches match).

- Fix: Settings -> Income, previous-salary and payable-tag amount boxes: Esc now throws away what you typed (a new amount, an emptied box, letters, a minus, a too-large amount), shows the saved amount again and takes the cursor out of the box; nothing is saved. Before, Esc did nothing and the cursor stayed. An amount with more than 9 digits before the decimal (e.g. 999999999999) is now refused with "Amount is too large (9 digits at most)." and never saved; leaving the box (Enter, Esc, Tab or a click elsewhere) puts the saved amount back and the status strip says it was not saved. Before, typing stopped at 9 digits without a word and the cut amount (999 999 999) was saved. The "New payable tag" amount refuses a too-large amount the same way; Esc in that line still clears it.
- Change: Reports, the large "Unearned income" and "Earnings from paid work" cards are gone in all four periods. The "Income lost or gained" and "Of which paid work" row is unchanged.
- Fix: Settings, a click on empty space in the settings pane (or on a heading or plain text) no longer puts the cursor in the first box of the section (the previous-salary box in Income). It happened with a real mouse after leaving a box, after clicking the section list, after switching windows or scrolling with the wheel.
- Fix: Settings -> Income, Enter in an emptied previous-salary or payable-tag box (or one with only letters or spaces) now puts the saved amount back and takes the cursor out of the box, the same as leaving it; before, the box stayed blank with the cursor in it. A minus or a 0 still stays with its message and the cursor. After a refused Add by mouse click, Esc or a click outside the "New payable tag" line now clears it and its message (and the same message in the status strip); before, only Esc with the cursor back in the line did.
- Fix: Settings -> Income, new payable tag: the amount box starts empty. Add (or Enter) with an empty amount, letters only, a minus or 0 is refused with the reason under the line and in the status strip (an earlier "Saved." is replaced); a tag with amount 0 is never saved. Tab or Shift+Tab out of the line keeps what you typed; only Esc or a click elsewhere clears it. After a mouse click on Add the cursor is in no box and Add no longer holds focus; a refused click keeps the typed text.
- Fix: Settings -> Income amount boxes: leaving the previous-salary or a payable-tag box empty (or with only letters typed) puts the saved amount back and says so; a 0 in a payable-tag box stays with "Amount must be more than 0." and is not saved. Enter or leaving with an invalid amount says "Not saved: ..." in the status strip. The cursor can no longer be moved into an Income box by anything except your own click, Tab or a return to the box you were in. The "= .../h" readout is hidden while the box holds no valid number, never "= —/h".
- Change: Settings -> Income, Enter and leaving: Enter in an amount box saves it and takes the cursor out of the box; Enter in the "New payable tag" line (name or amount) works like the Add button and then takes the cursor out. Clicking blank space or plain text beside an amount box now leaves the box (it saves, and stray typing changes nothing); before, the cursor stayed in the box. Removing a payable tag no longer drops the cursor into the next text box.
- Change: Settings -> Income, minus sign: a typed or pasted minus now stays in the box as one leading "-" ("-500"), and "Amounts can't be negative." stays under the box for as long as it is there, also after leaving the box. Nothing is saved and no tag can be added while it is there; delete the minus and the message goes. Enter in a box holding a minus (or an empty box) keeps the cursor there.
- Change: Settings -> Income money boxes (previous salary, payable-tag amounts, new-tag amount) now save when you leave the box or press Enter, not on every keystroke. Clicking the "Income" or "Paid work" heading takes the cursor out of any amount box so stray typing changes nothing. A typed minus shows "Amounts can't be negative." (sign handling changed again, see the entry above).

- Change: Reports shows two figures above the income card for each period (Today / This week / This month / This year): "Income lost or gained" (the same headline figure as before, which already includes paid work) and "Of which paid work" (the payable-tag total), both in EUR. The headline and the other cards are unchanged; no calculation changed.
- Change: the off-plan nudge now reads "Try blocking distracting apps and activities during working hours."
- Change: Settings -> Income money boxes (previous salary, each payable tag's monthly net, the new-tag amount) group thousands with a thin space as you type (2 925, 1 600, 14 000) and no longer show up/down arrows. The saved value is still a plain number.
- Change: Settings -> Income previous salary is laid out like a payable-tag row ("Previous salary -- monthly net (EUR)", the box, and "= EUR x/h").
- Change: in Settings -> Income, pressing Esc in the "New payable tag" line, or clicking outside it, clears both fields and adds nothing.
- Fix: after "Ask Claude" fills a reply that is not usable (Replace remaining tasks), the specific reason now stays under the reply box. Before, it vanished right after it appeared and only the reason line above said the reply was not usable. Typing in the box still clears it.
- Change: Add plan's "Ask Claude" no longer says "Claude's reply is in the box" for a reply that is clearly not a plan. It shows the reason under the reply box instead (not valid JSON, JSON that does not parse, or a missing id/name/phases). Nothing is imported on this check; Import still runs its full check.
- Change: "Ask Claude" never overwrites a reply already in the reply box (Replace remaining tasks and Add plan). With text in the box it sends nothing and says to clear the box first. The box is checked again after the first-use notice and when the answer arrives; text typed during the call discards the answer.
- Feature: optional "Ask Claude" in "Replace remaining tasks…" and "Add Plan". Settings -> AI holds an Anthropic API key (stored in Windows Credential Manager, shown never again after saving) and a model name, with Test connection and Remove key. With a key saved, the prompt can be sent to Claude from the dialog; a progress line with Stop appears, and the reply fills the reply box for the same validation and preview/import path as a pasted reply. Nothing is applied without the usual confirm. The first use shows a one-time notice of what is sent. Without a key, the copy-and-paste way is unchanged.
- Feature: "Replace remaining tasks…" v2. The copied prompt now lists every unfinished task in full (day, title, detail, mentor note, category, duration, tools), and step 1 has a "What should change?" field whose text goes into the prompt. An optional "Words that must be gone" field (comma-separated) makes the step 2 preview list every new task still mentioning those words (title, detail, mentor note or tools, case-insensitive) with a warning; the warning does not block Replace tasks, and the words are not saved.
- Fix: Plans page cards no longer squeeze the plan name into a narrow column. The name, meta line, due line and progress bar take the full card width (name up to two lines), and the action buttons sit on their own row beneath, wrapping to a second line on narrow windows. Same buttons, labels, order and behaviour.
- Feature: "Replace remaining tasks…" on each active plan (Plans page). Paste Claude's revised remaining tasks; unfinished tasks are replaced from the day after the last ticked task (day 1 if none is ticked; not clamped to today, so a far-behind plan's new tasks show as overdue), ticked tasks are kept untouched, and a preview shows the removed/added counts and the new finish date before anything is written.
- Feature: Reports page diary filters now accept multiple values per filter (category, app, page, tag). Within one filter, rows match any selected value (OR); across filters, conditions are AND-ed as before (e.g., Category {A} + Tag {X,Y} shows rows of category A with either tag X or Y). Empty selection on a filter means "no filter." Faceting is preserved: app/page option lists narrow by other active filters.
- Fix: Top Distractions and Time by App rows now use fixed-width columns for hours and EUR (Distractions only). All bars start and end at the same horizontal position, figures' right edges align per column, and bar fill is proportional to track width so it never overflows on narrow windows.
- Fix: working inside Planillium no longer logs as absence when tracker restarts (Settings save, diary re-categorisation, teaching rules). Stop() now flushes open sessions to the diary, so time spent in-app is preserved instead of being lost and re-detected as a "Welcome back" gap on the next poll.
- Feature: Reports page shows a consistent hourly cost for off-plan time across all sections. Per-hour value is now derived from configured monthly income (168 working hours per month: 21 days × 8 h), applied uniformly to both the income card's breakdown line and the Top Distractions list. Fixes an earlier over-inflation from dividing by only the off-plan hours in the displayed period.
- Feature: Insights now show EUR equivalents alongside off-plan hour figures (e.g. "5 h (€80.36)"), using the same hourly value as the income card. Off-plan time ratio now includes neutral minutes in its denominator (on-plan + neutral time) instead of on-plan only, providing a more accurate representation of distraction severity.
- Feature: Unemployed days now earn proportional plan-completion credit. When a plan has N tasks due and M are completed (M ≤ N), the day earns M/N of the daily idle-rate income credit, applied only to unemployed days. This allows partial completion to still register measurable progress toward income on days that might otherwise be marked zero.


- Change: Reports, Time diary: every filter list (Category, App, Page, Tag) has a "-" entry at the top that lists the entries with nothing in that field; it combines with the other entries and filters. The old "—" entry in the App list is replaced by "-". A new "Search in" box beside the search field limits the search to All fields (as before), App, Page, Description, Category or Tag; "Clear filters" resets it. Under the list, a line "Showing N of M" and links "Show 50 / 100 / 500 / 1000 more" (only sizes smaller than what is hidden) and "Show all" replace the single "Show 50 more". "Show all" stays on when the list refreshes by itself. The 300-entry limit for searches and All time is unchanged.
